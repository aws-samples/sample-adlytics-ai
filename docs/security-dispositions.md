Static scanners match syntax, so some of their records describe safe, reviewed code. Each row
below names one such class, why the mechanism the rule describes does not exist here, and where it
lives. Scan counts and run bookkeeping are kept with the operator's local scan register, not here.

**Marker form.** A suppression names the exact rule it suppresses, never a bare marker, and the
register ID sits on its own comment line above the flagged statement:

```python
# A-SQL-001: quoted identifiers, values bind as ?; see docs/security-dispositions.md
f"SELECT {columns}, {aggregates} "  # noqa: S608 — see the note above  # nosec B608
```

A Semgrep marker stands alone on the line above its match (`# nosemgrep: <namespaced rule id>`).
`scripts/check-publication-boundary.py` refuses a `nosec` that names anything but a reviewed
Bandit test ID and a `nosemgrep` without namespaced rule IDs, because Bandit reads a marker whose
IDs are all unknown as a blanket suppression of every test on that line. It reads both markers in
any letter case (O-MARKER-FORMS-001). Semgrep needs no comment leader: it honours a space then
`nosem` or `nosemgrep` anywhere on the line, so the gate holds the marker word to the rule wherever
it starts the line or follows whitespace, prose in a comment included, and also when glued to a
leader (O-MARKER-LEADERS-001). Prose names the word in backticks. The marker check reads only
`.py`, `.ts`, `.tsx`, `.js` and `.mjs` files, so SQL or HTML carrying a marker is checked only
when it is embedded in one of those. The release scanner
lists a marked Semgrep match with `status: suppressed`, as Semgrep documents; a scanner record with
no inline marker is dispositioned in that scanner by register ID.

**Markers ASH reads.** A detect-secrets record is suppressed by `pragma: allowlist nextline secret`
on the line above, followed by the register ID in parentheses; detect-secrets reports only the
first occurrence of a repeated value in a file, so each occurrence needs its own marker. A file
that cannot carry a comment (JSON, a generated file, the digest-pinned deep-input registry, a
fenced vector), and a Bandit test outside gate E's reviewed set, is suppressed by path and rule in
`.ash/.ash.yaml`, each entry citing its ID. The exported-template scan reads `.ash/templates.ash.yaml`
as `infra/scripts/export-scan-templates.ts` writes it, with one suppression per reviewed template
line and no path-wide secret suppression, so a new credential-shaped match stays open; the template IaC rules travel as resource metadata written by
`infra/lib/mixins/scan-dispositions.ts` (Checkov `checkov.skip`, cfn-nag `cfn_nag.rules_to_suppress`).

**Dispositions.** FALSE POSITIVE: the mechanism the rule names does not exist in this code.
NOT AFFECTED: a correct detection that cannot be exploited here (OpenVEX `not_affected`), recorded
with the owner's approval and a review trigger. NOT IN PUBLICATION SCOPE: the flagged artifact is
not tracked. ACCEPTED is used only for MEDIUM and LOW records. A real residual risk near a false positive is owned by its own finding, never folded
into these rows.

row gives the finding's meaning, its state and the tracked evidence its closure rests on; the
operator's local scan register keeps the scan bookkeeping. "Pending rescan" means the fix is in
the repository and the finding closes only when the next publication-scope scan no longer reports it.

**Git history.** Removing a fixture literal from the tree does not remove it from earlier commits,
and a history-aware secrets scan reads those. Owner decision, 2026-10-02 (UTC): history choice
deferred to publication; a history-aware scan before then will re-report the removed fixture
literals. The choice at publication is between fresh history and exact allowlists for those
literals; history is not rewritten before then.
